KABUTO // ONTOLOGY
● DB_POLICY: READ_ONLY_FROM_SIMULATION
1. Ontology Explorer
  • [Feature] JPX Data Ingestion

    JPX公式サイトから最新の銘柄一覧CSVを取得。FalkorDB上で一意性を担保しつつ、全上場企業をノードとしてMERGEする。operationPolicy: fact_write のため確認ダイアログ必須。

  • [Feature] Object Mapping

    各銘柄ノードに対し、ローカルのWindowsパス上のParquet（株価履歴）およびXBRL（財務報告書）の絶対パスをURIプロパティとして紐付ける。

  • [Feature] Metadata Schema

    33業種区分・市場区分・時価総額ランクなどの属性をオントロジープロパティとして定義。Geminiが引数を選ぶ際の制約（選択肢）となる。

  • [Logic] Manual Ingest Trigger

    ユーザーによる手動更新ボタン押下時のみ実行。差分データのみを効率的に更新する。

2. Causal Graph / Pipeline Builder (React Flow Canvas)
  • [Feature] Dynamic Graph Rendering (GRAPHモード)

    FalkorDBへのCypherクエリ結果（Nodes/Edges）をReact FlowのJSON形式に動的変換し描画する。ノードクリックでselection.idを更新する。

  • [Feature] Edge Weighted Visualization (GRAPHモード)

    因果関係の強さや相関係数に基づき、エッジの太さ・透過度を動的に変更し影響力を視覚化する。

  • [Logic] Semantic Zoom & Detail (GRAPHモード)

    ズームレベルに応じて表示情報を切り替え。縮小時は名称のみ、拡大時はPolarsで計算したリアルタイム数値を表示する。

  • [Logic] Graph Layout Strategy (GRAPHモード)

    D3-forceやDagreを活用し、数千ノードを重なりなく自動配置する。

  • [Logic] CoT Flow Rendering (COTモード)

    ctx-aipからexecution.mode: COTを受け取ったとき、Geminiの実行計画をReact Flowのノード・エッジとしてキャンバスに描画する。因果グラフとは切り替えて表示する。

  • [Feature] Pipeline Builder (PIPELINEモード)

    actionRegistryの各actionをノードとしてパレットに表示。ドラッグ&ドロップでキャンバスに配置し、エッジで繋ぐことで分析フローを構築する。入力パラメータ（selection_id等）はノード上で設定する。完成したパイプラインに名前・説明を付けてpipelineRegistryに登録する。

  • [Logic] Graph Mode Switching

    execution.modeに応じてキャンバスの内容を切り替える。GRAPH / COT / PIPELINEの3モードをヘッダーのタブで切り替え可能。

3. AIP Logic / CoT Debugger
  • [Feature] Gemini Function Calling

    selectionの型・actionRegistryの"when"・pipelineRegistryのlabelを元に、Geminiが最適な関数またはパイプラインを選択する。引数はFalkorDBのオントロジーから取得し推測に頼らない。temperature=0で決定論的に動作させる。

  • [Feature] CoT Visualization → Graph Mode

    Geminiのtext（思考過程）とfunctionCall（実行計画）を分離して表示。同時にctx-graphをCOTモードに切り替え、実行計画をReact Flowグラフとして可視化する。

  • [Feature] Approval Gate（承認ゲート）

    operationPolicyに従い承認レベルを自動判定。simulation: CoT表示後に承認ボタン。fact_write: 確認ダイアログ。承認後にexecute_scriptを呼び出す。FalkorDBへの変更は一切しない。

  • [Logic] execute_script Bridge

    Tauri側はexecute_script(script: String, args: JSON)のみを持つ汎用コマンド。新しいアクションの追加はスクリプトファイルを置くだけでリビルド不要。パイプラインはstepsを順次実行する。

  • [Feature] Simulation Report Output

    実行結果をreports/ディレクトリにJSONファイルとして出力。パイプライン実行時はreports/pipeline/に保存。FalkorDB（事実）とシミュレーション（仮説）を明確に分離する。

  • [Feature] Narrative Generation

    実行結果をGeminiが自然言語で要約。因果関係のパスを辿り「なぜこの数値になったか」のストーリーを生成する。

Gemini Chain of Thought
"INPEX(1605)の原油感応度を分析します。登録済みパイプライン「oil_sensitivity」が適切です。stress_test(+10%)とstress_test(-10%)を順次実行し、結果をレポートとして出力します。"
PROPOSED PIPELINE EXECUTION
pipeline: oil_sensitivity
input: { "selection_id": "1605" }
steps:
  1. stress_test(crude_oil, +10%)
  2. stress_test(crude_oil, -10%)
# SIMULATION OUTPUT (FalkorDB は変更しない)
→ reports/pipeline/oil_sensitivity_1605_20240426.json
4. Metrics Engine (Polars / Parquet)
  • [Feature] Sub-second Metric Calculation

    Polars-rsを活用し、巨大な株価Parquetファイルから特定期間の騰落率や財務KPIをサブ秒で抽出・チャート描画する。

  • [Feature] Cross-Object Correlation

    グラフで選択した複数ノードの時系列データを同期ロード。銘柄間・指標間の相関をリアルタイムで算出・表示する。

  • [Feature] Simulation Report Viewer

    ctx-aipが出力したレポートファイル（reports/**/*.json）を読み込み、シミュレーション・パイプライン実行結果を既存の時系列チャートに予測エッジ（別色）として合成表示する。過去レポートの読み込みも可能。

  • [Logic] Intelligent Caching

    一度読み込んだParquetの計算結果をメモリ上に保持。同一セッション内での高速な再描画とUI応答性を保証する。
